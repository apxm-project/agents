## What gets measured

1. **Per-arm joules consumed**: rocm-smi sidecar samples
   `total_watts` every 2s. Trapezoidal integration → arm-aggregate
   joules.
2. **Tasks completed per arm**: tau2 reports N=20 paired tasks.
3. **J/req per arm**: joules ÷ 20 tasks.
4. **Wall window per arm**: seconds between sidecar start and stop.

## What gets reported

Single CSV row + JSON record per arm:

| arm | n_tasks | total_joules | joules_per_task | mean_watts | sample_count | window_seconds |

Plus the **descriptive ratio** `apxm-on.J / flat-http.J`.

## Honest negatives anticipated

- **Idle power dominates ~50% of the per-sample budget** at this
  service config.
- **The two arms run sequentially**, prefix-cache state may differ.
- **Single-trial-per-task on the J/req axis**: 20 paired tasks but
  1 power trace per arm.
- **Tail latency variance**: like telecom N=20, one slow task can
  inflate the wall window. The descriptive J/req number is
  dominated by wall × mean_power, so tail-task variance is a
  per-cell artifact.
