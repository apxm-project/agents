# Create Your First APXM Agent

An APXM agent is one folder with an authored `agent.toml`, source files, and a
generated `integrity.toml` seal. The top-level manifest is both the
distribution identity and the runtime identity.

```text
<agent-id>/
  agent.toml
  integrity.toml              # generated by `apxm agent build`
  prompts/
  python/<agent-entry>.py      # or typescript/<agent-entry>.ts
  capabilities/
    <capability-id>/capability.toml
    <capability-id>/permission.toml
  skills/
```

Optional folders such as `README.md`, `examples/`, `tests/`, or `shared/` can
help operators and maintainers, but they are not required by the minimum
contract.

## Minimum `agent.toml`

The current schema id is `apxm.agent.v1`.

```toml
schema_version = "apxm.agent.v1"
id = "hello-agent"
version = "0.1.0"
license = "MIT"
display_name = "Hello Agent"
description = "A minimal APXM conversational agent."
kind = "agent"
domain = "examples"
capabilities = ["ping"]
skills = []

[source]
type = "local"

[compile]
entry = "python/hello_agent.py"
frontend = "python"

[runtime]
loop = "recv"
memory_space = "stm"
session_prefix = "hello"

[prompts]
persona = "prompts/persona.md"
```

Capabilities are flat ids. Their joined definitions live under
`capabilities/<id>/capability.toml` and
`capabilities/<id>/permission.toml`; `apxm agent sync` regenerates the
aggregate `capabilities/capabilities.toml` and `permissions.toml` files.

## Frontend Entry

Declare exactly one `[compile]` entry and its frontend. The package router sends
source-bearing packages through the normal Python or TypeScript frontend path;
only an entry-less package uses declarative synthesis.

Author a Python entry with `ConversationalAgent` from the APXM Python frontend
(`crates/compiler/frontend/python/apxm/conversational.py`):

```python
#!/usr/bin/env python3
from apxm import Agent, ConversationalAgent, ToolGroup, tool

@tool(name="ping")
def ping() -> str:
    """Health check."""
    return "pong"

researcher = Agent(name="researcher", instructions="Gather supporting facts.")

agent = ConversationalAgent(
    persona="You are a helpful APXM assistant.",
    memory_space="stm",
    tools=[ping],
    capability_groups=[ToolGroup.SKILLS],
    sub_agents=[researcher],
    loop="recv",
)

main = agent.compile()

if __name__ == "__main__":
    import sys
    if "--validate" in sys.argv:
        result = main.validate()
        print("VALID" if result.valid else "INVALID")
        for err in result.errors:
            print(f"  ERROR: {err}")
        sys.exit(0 if result.valid else 1)
    print(main.to_air())
```

TypeScript entries import `GraphBuilder` from `@apxm/frontend`, declare explicit
entry metadata, and follow the same `FrontendGraph -> apxm emit-air` path.
Neither frontend formats AIR itself.

Validate, compile, and build with the authority CLI:

```bash
dekk agents compile <agent-id-or-path>
dekk agents agent sync <agent-id-or-path>
dekk agents agent lint <agent-id-or-path>
dekk agents agent build <agent-id-or-path>
```

## Capabilities

Each capability needs a capability definition and a permission policy:

```toml
# capabilities/ping/capability.toml
id = "ping"
description = "Return a health-check response."
kind = "python_handler"
read_only = true
handler_module = "capabilities.handlers.ping"
handler_function = "ping"
```

```toml
# capabilities/ping/permission.toml
capability = "ping"
decision = "allow"
effect = "allow"
```

Runtime grants are session-scoped. Declaring a capability in TOML does not
grant authority to write-class tools; the operator must approve those per
conversation or workflow.

## Build

Run the agent toolchain from this repo:

```bash
dekk agents agent sync <agent-id-or-path>
dekk agents agent lint <agent-id-or-path>
dekk agents agent build <agent-id-or-path>
```

`apxm agent build` writes `integrity.toml`. The integrity chain excludes
`integrity.toml` itself, includes every recognized source file, and records the
root `hash` served by installed-agent APIs.

## Sub-Agents

Three shipped patterns are valid; pick by scope:

| Pattern | When to use | Source |
|---------|-------------|--------|
| `sub_agents=[Agent(...)]` | Specialists compiled into the same artifact | `apxm/conversational.py` |
| `g.spawn_agent` + `g.delegate` | Explicit delegation steps in a workflow graph | `examples/python/conversational/chat_agent.py` |
| `.apxmw` workflow execution | Server-owned workflow lifecycle for reusable multi-step work | `examples/workflows/` |

## Studio Integration

Studio discovers bundled agents under `workspace/studio/agents/<id>/` and
proxies installed agent records from apxm-server through:

- `GET /api/agents`
- `GET /api/agents/{id}`

Chat selects an agent with `agent_preset: "<id>"`. For Gao and other
server-owned chat agents, Studio creates an agent session through
`POST /v1/agents/{id}/sessions` and sends compact page/canvas context on each
turn.

See also: [Studio agents](../../../studio/agents/README.md).
