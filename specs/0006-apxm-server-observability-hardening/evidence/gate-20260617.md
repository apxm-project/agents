# 0006 Gate Evidence - APXM Server Observability Hardening

Date: 2026-06-17
Repo: `apxm`

## Scope Verified

- OTLP exporter wiring is present in `crates/tools/apxm-server/src/observability.rs` and initialized from server config/env in `src/lib.rs`.
- `/metrics` is mounted and returns Prometheus text with uptime and request counters.
- Safety middleware is mounted for configurable request body limits and token-bucket rate limiting.
- Auth policy auto-enables for non-loopback binds in startup and derives `PrincipalId` from validated bearer tokens.
- Shutdown now signals the shared `ShutdownCoordinator`, rejects new tracked requests while draining, waits for tracked HTTP work, then flushes rollout writers with timeout.
- Implementation comments were scanned for transient spec/checklist labels in the touched server/runtime/CLI surface.

## Fixes Applied During Gate Review

- `startup.rs` now passes the router's `ShutdownCoordinator` into shutdown handling before moving state into `build_app`.
- `drain_and_flush_rollouts` calls `signal_drain()`, awaits `wait_for_http_drain()`, and only then flushes rollout writers.
- `shutdown.rs` uses an atomic draining flag and returns a typed `503 server_draining` response for new tracked requests after drain starts.
- Added contract coverage proving authenticated protected requests use the bearer-derived principal before falling back to the public anonymous bucket.
- Corrected the quickstart gate command to `dekk apxm test -p apxm-server --test hardening_contract`; without `--test`, the wrapper filtered out the integration tests.

## Contract Coverage

- `metrics_endpoint_returns_prometheus_text`: verifies `/metrics` returns `200`, `apxm_server_uptime_seconds`, and `apxm_server_http_requests_total`.
- `rate_limit_returns_429_with_stable_code`: verifies configured limiter returns `429` with `rate_limit_exceeded`.
- `rate_limit_uses_authenticated_principal_before_public_fallback`: verifies middleware ordering and principal isolation between authenticated protected traffic and public anonymous traffic.
- `body_limit_rejects_oversized_payload`: verifies oversized payload returns `413`.
- `health_stays_available_under_default_config`: verifies default local config remains transparent.
- `startup::tests::shutdown_drain_waits_for_tracked_http_work`: verifies startup shutdown path waits for the active coordinator before rollout flush completion.
- `shutdown::tests::drain_waits_for_in_flight_to_clear`: verifies the coordinator wait barrier releases only after tracked work drops.

- Existing Rust warnings remain in pre-existing test/support surfaces; no new failing checks were introduced.
